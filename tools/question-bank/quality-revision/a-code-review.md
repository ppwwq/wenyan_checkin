# 有界程式覆核

範圍：`apply_quality.py`、`release.py`、`report.py`、`practice.mjs`、`queue.mjs`，以及合併／作答／題組相關測試；另追讀生成器的接入位置與 App 建組、提交、恢復、歷史顯示的呼叫路徑。按 code-review 技能進行只讀覆核，未修改程式。

本輪未發現可證實、需要阻擋合併的程式錯誤。

- 合併器逐題比對完整基線及題目雜湊，驗證改稿與審稿檔案雜湊、異作者身分、全包審稿覆蓋與處置。退修稿及舊雜湊不能合併。白名單排除 ID、memoryId 和 version。
- 修訂從不可變基線複製後遞增一次題目版本；重建仍從舊基線走同一流程。hold 只能停用新抽題，不能刪題或改歷史。
- practiceGroup 只影響新題組同組去重，未覆寫 memoryId；弱項篩選先執行，可選出同族已錯題。原資料未被排序或移位修改。
- 提交前不呼叫解析呈現；提交後只在 choice 模式且實際答案能對應到一個錯項時顯示所選錯项解析。空答、暫時不會、未知代號和 typing 不推定選項錯因。呈現文字均經 esc。
- 練習取 session.questions 的快照，提交保存當時 question，恢復取 session 而非重新從題庫載入；歷史從 attempt.payload.question 顯示當時答案與解析。新增題庫版本不回算舊答。
- report 的原題／新題屬作者審稿報告，本來會顯示答案；未被接入學生提交前題面。輸出經 HTML 轉義，無外部資源載入。

驗證方法：閱讀原始碼及既有相關測試；未重跑父代理已安排的全套測試，未作瀏覽器目視或真機驗收。內容來源是否足以支持每個新主張仍由逐題作者與交叉審稿負責，不能由以上結構檢查推定。
