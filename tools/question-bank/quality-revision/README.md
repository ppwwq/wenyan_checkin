## 簡單審核流程

1. **作者改稿**：三位 agent 按篇章分工；每題核原文、題幹、四項及解析，寫清三錯項的吸引點、誤讀與排除依據。
2. **交叉審稿**：另一位 agent 讀完整改稿及來源，檢查來源、唯一答案、干擾效力、猜題線索、題解一致五項；給通過／退修／待来源及具體理由。不是教師終審或真人盲審。
3. **修訂與合併**：作者修正，審稿者覆核受影響部分；主 agent 處理分歧。只有對應改稿精確雜湊的審查才能合併。待來源題暫停新抽題，舊作答不刪。
4. **程式驗證**：拒絕ID重複、基線漂移、越權欄位、舊審稿與錯誤高亮；核對來源定位、版本及重建結果，再執行App測試和建置。

## 檔案

- `manifest.json`：基線與首批清單；`inputs/`：原題和解析來源，僅供作者。
- `drafts/`：逐題改稿；`reviews/`：另一位agent的具體審稿。
- `release-manifest.json`：已核准的改稿及審稿精確雜湊。
- `release.py`：檢查交叉審稿及來源後產生發布manifest；不直接寫題庫。
- `apply_quality.py`：被完整題庫生成器調用；每次從同一基線重建。
- `test_apply_quality.py`：合併保護測試。
